# brand — decisions

Choices made where the spec (`docs/spec/MASTER_PROMPT.md` §11) and the brief
(`docs/design/input-control.md` §6) were silent or where the environment forced a different route.

| # | Decision | Why |
| --- | --- | --- |
| D1 | *(Superseded by D18–D20: the owner's logo replaced the dome arc.)* **The mark is a dome arc with a dot at its centre** (arc centre (32, 39), r 17, stroke 6, round caps; dot r 5.5), on a rounded tile (r 14/64). Two shapes, one colour, no text in the icon. The wordmark is a wordmark-weight version of the glyph (r 20, dot 6.5, same stroke 6 as the letters; D17) followed by "DoMe" drawn as monoline paths (stroke 6, cap height 40, x-height 28). | The spec asks for an original, simple wordmark and icon that stay readable at small sizes. At 16 px the arc is 1.5 px and the dot 2.75 px: still a dome and a dot (pixel-tested at 16 px). Letters as paths render identically everywhere and need no font licence; a system font stack covers all other text. The glyph echoes the existing PWA placeholder mark (dome arc on a dark tile) so the identity change is not jarring, but the geometry is new. |
| D2 | *(Extended by D19.)* **`scripts/export.mjs` renders the exports itself** (strict SVG-subset parser + signed-distance rasterizer + PNG/ICO writers, Node built-ins only) instead of using sharp/resvg/ImageMagick. | None of those can render SVG on this machine (`mobile-app/node_modules` has no image library; `mobile-app/scripts/make-icons.mjs` hand-codes pixels; ImageMagick's `rsvg-convert` delegate is missing; no cairo/cairosvg). Hand-coding pixels per size (the previous approach) cannot stay in sync with editable SVG sources. A small renderer for a subset that is *enforced* (anything else throws) keeps the SVGs as the single source of truth and the exports reproducible with `pnpm export`. The trade-off (no browser-grade AA, no fonts, no gradients) is documented in README and BRAND.md §8. |
| D3 | **Maskable and apple-touch exports are derived in the script** ("bleed" mode: drop the tile shape, fill the canvas with Night, scale the glyph group about the centre: 0.85 for maskable, 1.0 for apple-touch) rather than kept as extra SVG sources. | One geometry, four icon shapes; separate SVGs would drift. The `-tile` / `-glyph` id suffixes (D14) are the only coupling between the SVG sources and the script and are checked by the tests. |
| D4 | **Suffix `-dark` means "for dark backgrounds"** in every file name, sources and exports alike: `wordmark-dark.svg` has light letters, `icon-dark.svg` is a Slate tile with a Border-strong outline so it separates from a Night page, `tray-mono-on-dark-*.png` is the white glyph for dark taskbars (D12). `icon.svg` (Night tile) remains the default app icon on any surface. A test checks every suffixed export's paint luminance against its suffix. | Readers of the file list should not have to guess; the brief asks for light/dark variants of both assets. |
| D5 | **Tray icons ship in two forms**: colour tiles (`tray-*.png`, the recommended default, D15) and tinted mono glyphs (`tray-mono-on-dark-*` white for dark taskbars, `tray-mono-on-light-*` Ink for light taskbars; fallback for high-contrast/monochrome only), 16/32/48/256. No status colours are baked in. | `pc-agent/dome_agent/tray.py` currently draws its own status-coloured shape; the maintainer can show the colour tile with a status badge, or fall back to the mono glyph where Windows requires a single colour. The brand component must not decide the agent's status semantics. |
| D6 | **`.ico` files use 32-bit DIB entries with an AND mask for ≤ 48 px and a PNG entry for 256 px.** | The DIB form is read by every Windows version and by older favicon consumers; PNG-in-ICO at 256 px is the Vista+ convention and keeps the file at ~35 KB. Both forms were read back by Pillow and ImageMagick here (not Windows-device-tested). |
| D7 | *(Superseded by D20: the tokens are now measured from the owner's logo.)* **Colour tokens are the PWA's existing `--dome-color-*` values** (`mobile-app/src/styles.css`), named Night/Slate/Signal/Signal deep/Paper/Ink/Cloud in BRAND.md. The script's `TOKENS` and BRAND.md are kept in sync by a test, and every colour in the SVG sources must be a token. | The spec wants one identity across website, PWA, tray/setup and installer; the PWA already ships a palette, so brand adopts it rather than introducing a second one. |
| D8 | **Exports are committed** under `exports/` with a `manifest.json`, and `pnpm test`/`pnpm export:check` fail on drift. | Other components copy files by path; a reviewer must be able to see the actual bytes that will ship, and CI must catch an edited SVG whose exports were not regenerated (same pattern as the generated validators elsewhere in the repository). |
| D9 | **No dependencies of its own; lint/typecheck borrow `../mobile-app/node_modules`** via relative paths in `eslint.config.mjs` and `tsconfig.json` (`typeRoots`). `tsc --checkJs` runs with `strict`. | A brand package with a build toolchain would be the only reason to add a lockfile here; the mobile-app already pins the same ESLint/TypeScript versions used across the repository. |
| D10 | **Contrast numbers are stated as computed (WCAG formula) and Signal deep on Paper is documented as 3.8:1** (non-text level), with body text on light surfaces pointed at Ink. | The task forbids fabricated claims; the first draft of BRAND.md rounded this up and was corrected after computing the values. |
| D11 | **Differentiators in BRAND.md are the five from the spec, stated without comparisons** (straightforward setup, clear media targeting, useful Free controls, guided recovery, optional paid convenience), and the do/don't list forbids attaching claims to the mark. | Spec §11: no competitor comparisons, no "best", nothing fabricated. |
| D12 | **Mono tray exports renamed `tray-mono-light-*` → `tray-mono-on-dark-*` (white glyph) and `tray-mono-dark-*` → `tray-mono-on-light-*` (Ink glyph).** | Review finding: the old names used the suffix for the *glyph* colour, the opposite of D4, so a maintainer following D4 would have wired a near-black glyph onto a dark taskbar. `on-` makes the meaning explicit; the test "file-name suffix convention" fails if any `*-dark*` export paints dark or any `*-light*` export paints light. No consumer used the old names (mobile-app copies only `pwa/` and `favicon/`; pc-agent is not wired). |
| D13 | **`--check` and the drift test compare decoded pixels, not file bytes** (PNG: dimensions + RGBA; ICO: directory layout + every entry decoded, DIB via `decodeDib`, which also checks the AND mask against alpha). `manifest.json` is still compared as text. | The zlib stream inside a PNG is not stable across zlib builds, and `engines` allows any Node ≥ 22.12; byte equality would report "stale" for identical images on another Node and force re-committing binaries that differ only in compression. `pnpm export` still writes deterministic bytes for the Node it runs on. |
| D14 | **Every id in the sources is prefixed with the file name** (`dome-icon-title`, `dome-icon-tile`, `dome-icon-glyph`, `dome-wordmark-dark-letters`, ...); `aria-labelledby` points at the file's own `<title>`. The script recognises roles by suffix (`-tile`, `-glyph`), the parser rejects duplicate or non-identifier ids, bleed mode throws if a source has no tile shape. | BRAND.md §7 recommends inlining SVGs; with shared ids (`t`, `glyph`, `tile`) two inlined brand SVGs on one page produced duplicate ids and a screen reader could read the wrong title. Keeping `aria-labelledby` (rather than relying on `<title>` alone) is the most widely supported way to name an inline `role="img"` SVG. |
| D15 | **The colour tile is the recommended Windows tray icon; the mono glyph is a fallback for high-contrast/monochrome contexts only.** The glyph geometry is unchanged. | Review finding: at 16 px a single-colour arc over a dot reads like the one-bar Wi-Fi/hotspot indicator in the same notification area. The tile is distinctive on light and dark taskbars and `pystray` accepts RGBA. Changing the glyph (e.g. adding a baseline under the arc) would alter the identity across every icon and lockup; recorded as an option in KNOWN_ISSUES instead. |
| D16 | **Exports not in the plan are removed by `pnpm export` and reported as drift by `--check`** (only `.png`/`.ico` under `exports/`). | After a rename (D12) the old files would otherwise stay in `exports/` and a consumer could keep copying a stale name without any test noticing. |
| D17 | *(Superseded by D18: one traced drawing is used in every file.)* **The lockup glyph is a separate, wordmark-weight drawing** (arc r 20 centred (31, 40), dot r 6.5, stroke 6), documented in BRAND.md §1; the uniform-scaling rule applies per file. | Scaling the icon glyph (r 17, stroke 6) to r 20 would give a 7.06 stroke, heavier than the 6-unit letters; a monoline lockup needs one stroke weight. The review noted the previous BRAND.md text implied one glyph scaled everywhere. |
| D18 | **The logo was vectorised from the owner's raster by colour-separated tracing, then tidied by rule, not redrawn by eye.** Steps (scratch tooling, not committed; the SVGs are the source from now on): (1) per pixel, linear unmixing against the Navy background into white / Sky / Coral shares and an ink coverage; (2) coverage upscaled 4× (8× for REMOTE) bicubically with a light blur, sub-pixel iso-contours at 50 %; a first potrace pass (potracer) confirmed the outlines but left facets and wobble, so (3) each contour was refitted: corners where the outline turns sharply, straight runs found by length-aware tolerance and snapped to exact horizontal/vertical within 1.6°, the remaining spans smoothed with pinned ends and fitted with G1-continuous cubic Béziers (Schneider) to 0.22 px; (4) the colour layers were traced separately: the white layer extends 1.5 px under the tip and the cursor so there is no seam, the cursor was rebuilt from its seven corners with least-squares straight sides (stem sides made parallel, they differed by 3.4°) and one cubic for its curved left side, and the tip's diagonal cut is one straight line; (5) "REMOTE" was traced with settings for small letters. Result: rendered coverage differs from the owner's raster by 0.65 % on average over the whole lockup, edges agree to about 0.3 px of the 1536 px original. The icon reuses the higher-resolution wordmark mark: fitted to the owner's icon by overlap (scale 0.52967, offset measured), the two differ by 1–1.5 px of the 221 px icon, within what the soft, small icon raster can resolve. | The brief asks for a faithful vector logo (the D notch, the ring overlap, the cursor) with only tracing noise fixed. Rule-based tidying keeps every measured proportion while removing the source's compression wobble; one drawing in every file keeps the identity consistent, and a test now enforces that (uniform scale + shift between the lockups, `mark.svg` and `icon.svg`). |
| D19 | **The export script keeps its own rasterizer, extended to filled cubic/quadratic paths with fill rules, instead of switching to the bundled headless Chromium.** Curves are flattened by a second-derivative bound (0.02 units); fills are scan-converted with exact horizontal coverage and 16 sub-scanlines. | The committed exports are drift-checked pixel by pixel in CI. A browser's anti-aliasing changes between versions, so a browser-rendered export would report drift on every browser update and make the brand tests depend on a 100 MB binary. The extended renderer stays deterministic, needs nothing beyond Node, renders all 30 exports and the manifest in under a second, and matches Chromium 141 to a mean of 0.1–0.2/255 at icon and wordmark sizes (2.4/255 at 16 px), checked once here (README). |
| D20 | **Palette = the colours measured on the owner's logo** (Navy `#001441`, DoMe Blue `#0142fb`, Sky `#4281fa`, Coral `#f96054`, White, Ink `#000000`) **plus Sky light `#63a1fe`**, the lighter tip colour the owner's icon uses on the blue tile (measured `#63a1fe`; Sky would be 1.8 : 1 on the tile, Sky light is 2.5 : 1). The app icon is the DoMe Blue tile (corner radius 108/512, measured 21.0 %); maskable and apple-touch icons bleed DoMe Blue. `icon-dark.svg` is retired: a vivid blue tile separates from dark and light pages alike. The UI surface tokens in BRAND.md §2 are recommendations (Navy-tinted neutrals, contrast computed); the PWA's `styles.css` is owned by the app. | Faithful to the owner's artwork; one tile for every surface keeps the icon recognisable. |
| D21 | **Two lockups and a recolourable mark.** Besides the full lockup with REMOTE (`wordmark*.svg`), the compact lockup (`wordmark-compact*.svg`, same coordinates, REMOTE removed) is for headers: at 32 px the full lockup's REMOTE would be under 4 px tall. `mark.svg` paints its ring with `currentColor` so one inline file serves both themes; the accents stay Sky and Coral. ViewBoxes fit the ink (no built-in clear space); BRAND.md §4 states the clear space to add in layouts. | The website has a light/dark theme switch; inline SVG that follows `color` needs no second file, and tight viewBoxes let layouts align the visible edge of the logo. |
| D22 | **Consumers commit copies and the brand tests police them.** `scripts/sync-consumers.mjs` copies the extension icons (`exports/extension/`, 128 px with the Chrome Web Store's 16 px margin) and `windows/tray-256.png` into `browser-extension/public/icons/` and `pc-agent/dome_agent/assets/`; mobile-app keeps its own `make-icons.mjs`. Tests compare every copy (including `mobile-app/public/icons/`) with its export by decoded pixels. The tray loads the 256 px tile and draws the connection state as a status-coloured dot in a white ring at the bottom-right (the whole icon used to change colour); if the PNG cannot be read it draws a simplified tile with Pillow. | Each component builds without reaching into `brand/`, and a forgotten copy step fails CI instead of shipping an old logo. A badge keeps the brand tile recognisable in every state while the state stays visible at 16 px. |
