# brand — decisions

Choices made where the spec (`docs/spec/MASTER_PROMPT.md` §11) and the brief
(`docs/design/input-control.md` §6) were silent or where the environment forced a different route.

| # | Decision | Why |
| --- | --- | --- |
| D1 | **The mark is a dome arc with a dot at its centre** (arc centre (32, 39), r 17, stroke 6, round caps; dot r 5.5), on a rounded tile (r 14/64). Two shapes, one colour, no text in the icon. The wordmark is a wordmark-weight version of the glyph (r 20, dot 6.5, same stroke 6 as the letters; D17) followed by "DoMe" drawn as monoline paths (stroke 6, cap height 40, x-height 28). | The spec asks for an original, simple wordmark and icon that stay readable at small sizes. At 16 px the arc is 1.5 px and the dot 2.75 px: still a dome and a dot (pixel-tested at 16 px). Letters as paths render identically everywhere and need no font licence; a system font stack covers all other text. The glyph echoes the existing PWA placeholder mark (dome arc on a dark tile) so the identity change is not jarring, but the geometry is new. |
| D2 | **`scripts/export.mjs` renders the exports itself** (strict SVG-subset parser + signed-distance rasterizer + PNG/ICO writers, Node built-ins only) instead of using sharp/resvg/ImageMagick. | None of those can render SVG on this machine (`mobile-app/node_modules` has no image library; `mobile-app/scripts/make-icons.mjs` hand-codes pixels; ImageMagick's `rsvg-convert` delegate is missing; no cairo/cairosvg). Hand-coding pixels per size (the previous approach) cannot stay in sync with editable SVG sources. A small renderer for a subset that is *enforced* (anything else throws) keeps the SVGs as the single source of truth and the exports reproducible with `pnpm export`. The trade-off (no browser-grade AA, no fonts, no gradients) is documented in README and BRAND.md §8. |
| D3 | **Maskable and apple-touch exports are derived in the script** ("bleed" mode: drop the tile shape, fill the canvas with Night, scale the glyph group about the centre: 0.85 for maskable, 1.0 for apple-touch) rather than kept as extra SVG sources. | One geometry, four icon shapes; separate SVGs would drift. The `-tile` / `-glyph` id suffixes (D14) are the only coupling between the SVG sources and the script and are checked by the tests. |
| D4 | **Suffix `-dark` means "for dark backgrounds"** in every file name, sources and exports alike: `wordmark-dark.svg` has light letters, `icon-dark.svg` is a Slate tile with a Border-strong outline so it separates from a Night page, `tray-mono-on-dark-*.png` is the white glyph for dark taskbars (D12). `icon.svg` (Night tile) remains the default app icon on any surface. A test checks every suffixed export's paint luminance against its suffix. | Readers of the file list should not have to guess; the brief asks for light/dark variants of both assets. |
| D5 | **Tray icons ship in two forms**: colour tiles (`tray-*.png`, the recommended default, D15) and tinted mono glyphs (`tray-mono-on-dark-*` white for dark taskbars, `tray-mono-on-light-*` Ink for light taskbars; fallback for high-contrast/monochrome only), 16/32/48/256. No status colours are baked in. | `pc-agent/dome_agent/tray.py` currently draws its own status-coloured shape; the maintainer can show the colour tile with a status badge, or fall back to the mono glyph where Windows requires a single colour. The brand component must not decide the agent's status semantics. |
| D6 | **`.ico` files use 32-bit DIB entries with an AND mask for ≤ 48 px and a PNG entry for 256 px.** | The DIB form is read by every Windows version and by older favicon consumers; PNG-in-ICO at 256 px is the Vista+ convention and keeps the file at ~35 KB. Both forms were read back by Pillow and ImageMagick here (not Windows-device-tested). |
| D7 | **Colour tokens are the PWA's existing `--dome-color-*` values** (`mobile-app/src/styles.css`), named Night/Slate/Signal/Signal deep/Paper/Ink/Cloud in BRAND.md. The script's `TOKENS` and BRAND.md are kept in sync by a test, and every colour in the SVG sources must be a token. | The spec wants one identity across website, PWA, tray/setup and installer; the PWA already ships a palette, so brand adopts it rather than introducing a second one. |
| D8 | **Exports are committed** under `exports/` with a `manifest.json`, and `pnpm test`/`pnpm export:check` fail on drift. | Other components copy files by path; a reviewer must be able to see the actual bytes that will ship, and CI must catch an edited SVG whose exports were not regenerated (same pattern as the generated validators elsewhere in the repository). |
| D9 | **No dependencies of its own; lint/typecheck borrow `../mobile-app/node_modules`** via relative paths in `eslint.config.mjs` and `tsconfig.json` (`typeRoots`). `tsc --checkJs` runs with `strict`. | A brand package with a build toolchain would be the only reason to add a lockfile here; the mobile-app already pins the same ESLint/TypeScript versions used across the repository. |
| D10 | **Contrast numbers are stated as computed (WCAG formula) and Signal deep on Paper is documented as 3.8:1** (non-text level), with body text on light surfaces pointed at Ink. | The task forbids fabricated claims; the first draft of BRAND.md rounded this up and was corrected after computing the values. |
| D11 | **Differentiators in BRAND.md are the five from the spec, stated without comparisons** (straightforward setup, clear media targeting, useful Free controls, guided recovery, optional paid convenience), and the do/don't list forbids attaching claims to the mark. | Spec §11: no competitor comparisons, no "best", nothing fabricated. |
| D12 | **Mono tray exports renamed `tray-mono-light-*` → `tray-mono-on-dark-*` (white glyph) and `tray-mono-dark-*` → `tray-mono-on-light-*` (Ink glyph).** | Review finding: the old names used the suffix for the *glyph* colour, the opposite of D4, so a maintainer following D4 would have wired a near-black glyph onto a dark taskbar. `on-` makes the meaning explicit; the test "file-name suffix convention" fails if any `*-dark*` export paints dark or any `*-light*` export paints light. No consumer used the old names (mobile-app copies only `pwa/` and `favicon/`; pc-agent is not wired). |
| D13 | **`--check` and the drift test compare decoded pixels, not file bytes** (PNG: dimensions + RGBA; ICO: directory layout + every entry decoded, DIB via `decodeDib`, which also checks the AND mask against alpha). `manifest.json` is still compared as text. | The zlib stream inside a PNG is not stable across zlib builds, and `engines` allows any Node ≥ 22.12; byte equality would report "stale" for identical images on another Node and force re-committing binaries that differ only in compression. `pnpm export` still writes deterministic bytes for the Node it runs on. |
| D14 | **Every id in the sources is prefixed with the file name** (`dome-icon-title`, `dome-icon-tile`, `dome-icon-glyph`, `dome-wordmark-dark-letters`, ...); `aria-labelledby` points at the file's own `<title>`. The script recognises roles by suffix (`-tile`, `-glyph`), the parser rejects duplicate or non-identifier ids, bleed mode throws if a source has no tile shape. | BRAND.md §7 recommends inlining SVGs; with shared ids (`t`, `glyph`, `tile`) two inlined brand SVGs on one page produced duplicate ids and a screen reader could read the wrong title. Keeping `aria-labelledby` (rather than relying on `<title>` alone) is the most widely supported way to name an inline `role="img"` SVG. |
| D15 | **The colour tile is the recommended Windows tray icon; the mono glyph is a fallback for high-contrast/monochrome contexts only.** The glyph geometry is unchanged. | Review finding: at 16 px a single-colour arc over a dot reads like the one-bar Wi-Fi/hotspot indicator in the same notification area. The tile is distinctive on light and dark taskbars and `pystray` accepts RGBA. Changing the glyph (e.g. adding a baseline under the arc) would alter the identity across every icon and lockup; recorded as an option in KNOWN_ISSUES instead. |
| D16 | **Exports not in the plan are removed by `pnpm export` and reported as drift by `--check`** (only `.png`/`.ico` under `exports/`). | After a rename (D12) the old files would otherwise stay in `exports/` and a consumer could keep copying a stale name without any test noticing. |
| D17 | **The lockup glyph is a separate, wordmark-weight drawing** (arc r 20 centred (31, 40), dot r 6.5, stroke 6), documented in BRAND.md §1; the uniform-scaling rule applies per file. | Scaling the icon glyph (r 17, stroke 6) to r 20 would give a 7.06 stroke, heavier than the 6-unit letters; a monoline lockup needs one stroke weight. The review noted the previous BRAND.md text implied one glyph scaled everywhere. |
